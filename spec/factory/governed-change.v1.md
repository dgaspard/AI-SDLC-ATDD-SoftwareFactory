# START-02 governed local change contract v1

Specification for human review. Canonical milestone status is in BACKLOG.md.
This specifies the update slice of lifecycle work, not a general agent platform.
Create/delete below concern files in one task; application provisioning, repository
creation/deletion, infrastructure, data migration and deployment are out of scope.

## Reuse and invocation

Implement a thin coordinator at `tools/factory/change.mjs` around existing
`core.mjs` canonical path/trust/tree checks, `processes.mjs` process-group cleanup,
`consumer.mjs verify --mode full`, and the consumer's existing policy/adapters.
Do not duplicate a runner, test scheduler, evidence-v1 generator, package manager,
model SDK, planner, tool marketplace or approval engine. No implicit install/fetch.

Proposed commands (not current capabilities):

```
node <pinned-factory>/tools/factory/change.mjs run --root <consumer> --task <relative-json> --authority <external-json> --runner <external-json> --output <new-external-directory>
node <same-pinned-factory>/tools/factory/change.mjs check --evidence <external-change-evidence.json>
```

Unknown arguments/fields, noncanonical unsafe paths or invalid types fail closed.
Protected drift is TRUST_INVALID; other original dirt is REQUEST_INVALID. The root must be a clean Git checkout with exact `startRevision`; no implicit stash,
reset, checkout or modification of the original, its index, refs or untracked files.
The task and frozen changed requirements MUST already be committed at that revision.
The original may have a Git remote but this operation neither fetches nor pushes.

`task` is a protected consumer JSON object with exactly these fields:
`schemaVersion:1`, `id` (safe `[a-z0-9-]+`), `requirementPaths` (nonempty existing
protected relative regular files), `intent` (nonempty text), and `permissions` with
`create`, `update`, `delete` (arrays of unique literal relative regular-file paths).
No glob, directory wildcard, absolute path, `..`, `.git`, symlink or hardlink alias.
Create targets must not exist; update/delete targets must exist at start. Sets are
pairwise disjoint. A rename requires an explicit delete plus create. Empty sets grant
nothing. No edits outside this manifest, including dependency locks or scripts,
unless independently approved as application implementation and explicitly listed.

Authority is a trusted external owner-supplied snapshot, not selected or generated by
the coding runner. Exact fields: `schemaVersion:1`, `taskSha256`, `startRevision`
(full lowercase 40-hex), `consumerRepository`, `factoryRevision` (full lowercase 40-hex),
`consumerConfig` (protected relative path), `consumerTrust` (absolute external path to
existing consumer-v1 snapshot), `runnerSha256`. Bind raw bytes; validate against the
human-reviewed commit, never infer human approval from a Git author, hash or runner.
Record resolved consumer/factory revisions, configuration and authority hashes before
any execution. Factory HEAD must be clean, match authority and the consumer config
pin. An upgrade requires a separately reviewed consumer pin change and freeze.

Task, requirements, tests, fixtures, policies, trust/config/manifest, verification
commands, runner authority and all approval machinery remain protected against
create/update/delete. Deny rules take precedence over task grants. `.github/`,
`.claude/`, `AGENTS.md`, `CLAUDE.md`, all configured protected paths and `.git` are
unconditionally unavailable for runner writes. A source-delete grant is only a literal
file authorization for this task; it does NOT authorize specification deletion,
production-data deletion, infrastructure deletion or repository removal. External
paths and the original checkout are never writable, even through aliases. Reject
bad grants and unsafe output destinations before running any consumer/runner command.
Resolve every existing ancestor to its actual destination and recheck before use.

## Isolation, runner and credentials

Use a private clone with its own Git metadata under the new external output, branch
`factory/change/<task-id>/<run-id>`; no shared object alternates or writable common Git
directory. Never use a linked worktree exposing the original repository's writable
common directory. The coordinator creates this branch; the runner cannot write Git
metadata, commit, approve, freeze, fetch, push or merge. Retain its final diff rather
than automatically committing. No force push or automatic original-tree application.

The owner supplies a reviewed launcher descriptor outside runner-writable space:
`schemaVersion:1`, `kind:"real"|"fixture"`, `argv` (nonempty argv, no shell evaluation),
`executableSha256`, `inputs` (array of `{path,sha256}` for every script/module/config used by the launcher, absolute read-only regular files), `timeoutMs` (positive <= 1800000), `network:"none"|"model-proxy"`.
The descriptor, executable and every declared input are read-only, digest-bound by authority. Reject undeclared launcher code/config dependencies; the launcher environment must be provisioned immutably. Missing inputs are tooling failures; existing bytes that differ are trust failures. `kind:fixture`
is ONLY a protocol regression test double; never a real PetClinic demonstration.
Unavailable launcher or unsupported mandatory isolation is TOOLING_UNAVAILABLE,
not fallback to unrestricted exec, a fake edit script, interactive personal login or
an assumed coding-agent API. The specific real launcher is an open implementation
prerequisite; no available API, credential, provider or sandbox is claimed by this spec.

Launcher stdin is one JSON request `{schemaVersion:1,runId,workspace,task,limits}`.
`task` is the validated task object; `limits` includes the validated file permission
sets, read-only roots, network mode and deadline. Launcher stdout is one JSON response
`{schemaVersion:1,runId,status:"finished"|"failed"|"denied",exitCode,violations:[]}`.
Each violation is `{operation:"create"|"update"|"delete",path}`. Diagnostics go to
stderr, captured as a restricted artifact. Malformed/truncated response fails, even
when process exit is zero. Runner output is never authority that tests passed.

A real launcher must provide OS-enforced filesystem and process/network isolation:
only task-granted implementation files and private scratch writable; protected files,
Git metadata, original checkout, factory, trusted inputs and coordinator evidence are
not writable. Denied write attempts are reported even if the file remains unchanged.
No inherited HOME, SSH agent, Git credential helper, cloud/App/PAT secrets, host socket,
Docker socket or unrestricted host shell. Use an allowlisted environment and private
HOME. If a coding provider needs credentials, an owner-configured broker outside the
sandbox holds them and exposes only the model endpoint, not GitHub/cloud operations;
runner sees a scoped per-run channel, not the underlying credential. Network none is
the default; model-proxy permits only that broker, not arbitrary internet access.
Do not record secrets, auth headers or prompts containing secrets in evidence.

Post-run hashes are drift detection, NOT a substitute for OS write denial. Worktree
separation and prompt instructions alone do not fulfill bounded permissions. A real
launcher must pass the separate mandatory conformance checklist below before use.

## Phases, verification and recovery

Persist a coordinator-owned journal atomically: VALIDATED, ISOLATED, IMPLEMENTING,
IMPLEMENTED, VERIFYING, FINALIZING, then terminal result. Flush run ID, source identity,
branch, isolated root, grants and owned process IDs before launch. Never overwrite an
existing run directory. Capture a binary diff including new files and deletions, modes,
and exact changed-path list against startRevision. Any unexpected change is denied.
A no-op is IMPLEMENTATION_FAILED for this demonstration, not a successful change.

On runner completion, stop its entire owned process group and confirm descendants
exit before accepting a candidate. Check all frozen inputs and original checkout
fingerprints again. Copy the candidate inputs into a separate verifier workspace
whose tests/policy/approval bytes come from the approved startRevision; install no
runner-supplied tooling and inherit no runner environment or processes. Disable Git
hooks/filters and credential discovery in isolated clones without changing original
configuration. Verification uses a separately provisioned, least-privilege local
profile allowing only declared loopback application services and test tooling. No
coding credentials are present in this profile. A trusted host/CI must keep the runner
from writing this workspace/evidence or influencing the verifier's process environment.

Run the existing pinned consumer verifier in full mode, with trusted required suite
selection. Neither task nor runner can reduce the gate. Keep original evidence-v1 and
consumer-evidence.v1 meanings. All suites must pass on the exact candidate input tree.
After verifier shutdown/cleanup completes, recheck candidate, original, protected and
factory identities, validate consumer envelope/artifact hashes, and only then finalize
the new governed-change evidence. Test failure, missing/stale evidence or cleanup
failure cannot become success even if some later process exits zero.

SIGINT/SIGTERM: stop and await owned processes, journal INTERRUPTED, retain isolated
files/diff/logs; never reset original or delete failed work. If SIGKILL/host loss prevents
finalization, a nonterminal journal is incomplete, never successful. `check` rejects it.
Recovery is inspection/export followed by a NEW invocation after confirming cleanup;
no automatic resume, reuse of old passes, worktree deletion or rollback of application
data. Manual deletion of a retained run requires a separate explicit human action.

## Result and evidence contract

Stdout is one JSON object `{schemaVersion:1,runId,status,category,runDirectory,evidence}`;
logs on stderr. Generate a UUID runId per invocation, including preflight failure; runDirectory is null until isolation creates the new directory. `evidence` is null before final evidence exists; otherwise it is an absolute canonical path inside runDirectory. runDirectory, isolation.workspace and isolation.verificationRoot are absolute canonical paths. Success status is
`VERIFIED_CANDIDATE` (real runner) or `SIMULATED_VERIFIED` (fixture runner), never an
approval, merge, deployment or claim of real-agent proof for a fixture. Both exit 0
but only VERIFIED_CANDIDATE satisfies real demonstration acceptance. `FAILED` and
`INTERRUPTED` always exit nonzero. Preflight failure creates no run directory or child.

| Exit | Category | Required outcome |
|---|---|---|
| 2 | REQUEST_INVALID | Invalid root/task/grant/output; no execution |
| 3 | VERSION_INCOMPATIBLE | Wrong/dirty factory or mismatched pin; no execution |
| 4 | TRUST_INVALID | Unfrozen/unapproved requirement/task/config or changed authority; no execution |
| 5 | TOOLING_UNAVAILABLE | No real runner/isolation/verifier tooling; no fake fallback |
| 6 | PERMISSION_DENIED | Attempted protected/out-of-scope create/update/delete; retain denial and original unchanged |
| 7 | ACCEPTANCE_FAILED | Full consumer verifier nonzero; include its exit/category, no successful change evidence |
| 8 | EVIDENCE_INVALID | Missing/malformed/stale identity/artifact/diff; no success |
| 9 | COORDINATOR_ERROR | Unexpected failure or unconfirmed cleanup; no success |
| 10 | IMPLEMENTATION_FAILED | Runner failure/malformed response/no-op/timeout; retain work |
| 130 | INTERRUPTED | Observed interrupt; retained work, terminated owned processes |

First phase failure is primary, but cleanup failure overrides success and interruption
with exit9; include all failures. Do not reinterpret consumer exit7 as runner failure.

`governed-change-evidence.v1.json` is separate from existing envelopes. Required fields:
`schemaVersion:1`, `runId`, `status`, `category`, `runnerKind`, `startedAt`, `finishedAt`,
`consumer:{repository,startRevision,startTreeSha256,candidateTreeSha256}`,
`factory:{revision}`, `authoritySha256`, `taskSha256`, `runnerDescriptorSha256`,
`requirements:[{path,sha256}]`, `permissions`, `isolation:{workspace,verificationRoot,branch}`,
`implementation:{exitCode,violations}`, `verification:{exitCode,envelopePath,envelopeSha256}`,
`diff:{path,sha256,changes:[{operation,path,beforeSha256,afterSha256}]}`,
`cleanup:{runnerStopped,verifierStopped}`, `originalUnchanged`, `artifacts:[{path,sha256}]`.
Failure envelopes retain the same fields, using null for phases not reached; never invent
suite results. Hash regular input bytes and modes using existing consumer tree rules.
Diff and artifact paths are run-relative and cannot escape through shortcuts. verification.envelopePath is relative to isolation.verificationRoot; its referenced consumer artifacts are verified there. Evidence
and its journal are coordinator-owned, runner read-only. No self-recursive hash.

`check` rereads retained original/candidate/verifier inputs, task/authority, factory and
artifact hashes after confirming no owned writers remain; validates terminal journal,
permission diff, complete consumer proof and exact identities. Any subsequent candidate
edit, added file, deletion, changed mode, requirement/pin/evidence edit or swapped diff
returns exit8 even if an old envelope says success. Diagnostic checking never updates
old evidence to bless drift. Successful evidence is unsigned local proof, not approval.

## Required proof and test ownership

`spec/tests/factory/governed-change.test.js` is a neutral red contract suite for the
future CLI. Its explicit fixture launcher exercises protocol and state transitions;
it is NOT a coding agent or permission sandbox. Real demonstration additionally MUST
run owner-reviewed launcher conformance: direct and symlink/hardlink attempts at every
protected operation; original/common-Git and factory writes; credential/environment
leak probes; network escape; surviving child writers; denied-attempt audit capture;
verification workspace write attempt; interrupted process cleanup. Each must be denied
before mutation, with original/frozen bytes unchanged. Record launcher/platform version,
digests and logs. Missing real conformance is a blocker, never a skipped passing check.

PetClinic acceptance is maintained only in its repository: D-67 and the preferred-vet
conflict feature/API delta. The implementation task may update only
`services/customer/server.js`; create/delete grants are empty. Runtime/performance,
all fourteen consumer suites and evidence-v1 semantics remain binding. No service
implementation change is authorized in this specification phase. A later real proof
needs a released workflow implementation SHA, reviewed consumer config pin upgrade,
human freeze/commit, renewed external authority, and a real constrained launcher.

## Syscall-time target authorization (SCT)

The first implementation profile remains Linux arm64, update-only, with immutable
container inputs, an unprivileged coding process, private scratch, network-none
qualification and independent protected audit storage. This amendment authorizes
no additional host privilege, privileged container, cloud access or real activation.

A mutation attempt must be classified from independently established syscall-time
identity, never nominal pathname text, errno alone or post-run realpath. Before
classifying, stop all relevant tracee threads and descendants, including those
that can modify syscall argument memory, shared file tables or filesystem context.
Establish stable process, root, cwd, dirfd, mount, syscall arguments and
target/nearest-existing-parent identity as applicable. Resume only the selected
syscall thread through the attempted operation's disposition; keep every other
relevant writer stopped, or prove equivalent exclusion. A concurrent rename,
symlink substitution, argument-buffer rewrite, descriptor reuse or cwd change must
not invalidate the decision. Unaccounted pending kernel/asynchronous writers make
the target unresolved. If the mechanism cannot establish this invariant under
current capabilities, stop with TOOLING_UNAVAILABLE; do not relax isolation.

Report authorized private scratch, task-granted implementation mutation,
out-of-scope mutation, or unresolved. A failed private scratch operation may be
nonblocking only when the independent observer proves its authorization and
coverage. ENOENT/EEXIST do not themselves prove authorization. An unresolved target,
unsupported syscall form, missing descendant coverage or incomplete observer stream
prevents successful qualification. Out-of-scope create/update/delete attempts remain
PERMISSION_DENIED even if no bytes changed. Writable /dev/tty opens have no implicit
exception. No generic /tmp prefix or startup-error allowance is permitted.

Retain the original trace and independent identity/disposition records in protected
observer storage, bound to the run and immutable observer/runner inputs. Confirm
all owned processes stopped before collecting, hashing or validating those records.
Observer interruption, lost coverage or stale records cannot produce success. An
observed coordinator interrupt remains INTERRUPTED; inability to confirm cleanup
remains COORDINATOR_ERROR under the existing precedence rules.

The mandatory additional conformance cases are enumerated in
`spec/factory/syscall-observer-cases.v1.json`. The trusted qualification harness must
execute the actual synchronized workloads under the observer, assert their individual
outcomes and retain trace/identity/cleanup evidence. A reported case name, fabricated
receipt, injected snapshot, parser-only test or fixture launcher cannot satisfy these
platform cases. Missing tooling is an explicit blocking result, never a passing or
skipped case. Portable regression tests may supplement but not replace this proof.

The concurrency case must use deterministic barriers that place a competing writer
at the target replacement boundary; timing sleeps or repeated races are insufficient.
The coverage/interruption cases deliberately disable observation and must demonstrate
that a workload's successful exit cannot produce successful qualification. The
baseline must run the actual pinned CLI through the neutral local tool roundtrip;
synthetic model responses remain credential-free protocol fixtures, not live inference.

All prior governed-change conformance remains mandatory. Passing SCT is component
qualification only: it does not enable the real coordinator, approve a consumer pin,
implement PetClinic, approve/merge a diff or authorize deployment.
